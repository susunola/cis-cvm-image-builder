# ciscvm — TencentOS CIS Image Builder

Produce CIS-hardened TencentOS golden images on Tencent Cloud. A configuration-driven
CLI tool that spins up an ephemeral CVM, applies the bundled cis-os engine, and captures
the result as a custom image — all from `ciscvm.toml`.

Supported: **TencentOS Server 3 / 4**. The CIS engine (`cis_engine.py` + `rules.json`)
is bundled locally in `roles/` — no Ansible Galaxy, no network dependency at build time.
The gate runs inside the Ansible role (`cis_fail_on_findings: true`): if any findings
remain after remediation, the build fails before the image is created.

## Prerequisites

| Requirement | Details |
|---|---|
| **Python** | >= 3.11 (stdlib only — zero pip dependencies) |
| **Packer** | >= 1.9 with `packer-plugin-tencentcloud` |
| **Tencent Cloud** | Sub-account with `cvm:RunInstances`, `cvm:CreateImage`, `cvm:DescribeImages`, `cvm:CopyImage`* |
| **Network** | Dedicated VPC + subnet + security group (inbound 22, restricted to build machine egress IP) |
| **Source Image** | TencentOS Server 3 or 4 public image ID |

\* `cvm:CopyImage` only needed with cross-region copy.

Credentials via environment variables only:

```bash
export TENCENTCLOUD_SECRET_ID=AKIDxxxx
export TENCENTCLOUD_SECRET_KEY=xxxx
```

## Quick Start

```bash
# 1. Bootstrap configuration
python3 ciscvm.py init

# 2. Edit ciscvm.toml with VPC / subnet / SG / TencentOS source image ID

# 3. Pre-flight check
python3 ciscvm.py preflight

# 4. Dry-run: render + packer validate
python3 ciscvm.py validate

# 5. Build the hardened image
python3 ciscvm.py build

# Optional: clean up rendered files
python3 ciscvm.py clean
```

| Flag | Default | Description |
|---|---|---|
| `--config <path>` | `./ciscvm.toml` | Configuration file |
| `--workdir <dir>` | `./.ciscvm-build` | Rendered output directory |
| `--quiet` | — | Suppress tool output (validate / build) |
| `-y` / `--yes` | — | Skip build confirmation prompt |

## Configuration

`ciscvm.toml` is the single source of truth:

```toml
[build]
profile             = "tencentos3"         # tencentos3 | tencentos4
region              = "ap-guangzhou"
zone                = "ap-guangzhou-4"
instance_type       = "S5.MEDIUM2"
source_image_id     = "img-xxxxxxxx"       # Replace with actual TencentOS image ID
vpc_id              = "vpc-xxxxxxxx"
subnet_id           = "subnet-xxxxxxxx"
security_group_id   = "sg-xxxxxxxx"
associate_public_ip = true

[image]
name_prefix  = "tencentos3-cis"
copy_regions = ["ap-shanghai"]            # [] to disable cross-region copy

[cis]
level = 1                                 # 1 or 2

[cloud]
secret_id_env  = "TENCENTCLOUD_SECRET_ID"
secret_key_env = "TENCENTCLOUD_SECRET_KEY"

[meta]
os_tag    = "tencentos-3"
benchmark = "CIS-v1.0.0"
```

### Config Reference

| Section | Field | Type | Description |
|---|---|---|---|
| `[build]` | `profile` | string | `tencentos3` or `tencentos4` |
| | `region` | string | Tencent Cloud region, e.g. `ap-guangzhou` |
| | `zone` | string | Availability zone, e.g. `ap-guangzhou-4` |
| | `instance_type` | string | CVM instance spec, e.g. `S5.MEDIUM2` |
| | `source_image_id` | string | TencentOS public image ID |
| | `vpc_id` / `subnet_id` | string | Network identifiers |
| | `security_group_id` | string | Must start with `sg-` |
| | `associate_public_ip` | bool | Assign public IP to build instance |
| `[image]` | `name_prefix` | string | Prefix for the output image name |
| | `copy_regions` | []string | Regions to replicate to (empty = skip) |
| `[cis]` | `level` | int | 1 (Level 1) or 2 (Level 2) |
| `[cloud]` | `secret_id_env` | string | Env var for Tencent Cloud Secret ID |
| | `secret_key_env` | string | Env var for Tencent Cloud Secret Key |
| `[meta]` | `os_tag` | string | Tag value for the output image |
| | `benchmark` | string | CIS benchmark version tag |

## Architecture

### Build Pipeline

```
Build Machine                              Tencent Cloud
┌─────────────┐                           ┌──────────────────┐
│ ciscvm.py   │── packer build ──────────▶│ Ephemeral CVM    │
│             │                           │                  │
│ ciscvm.toml │                           │ 1. Install ansible│
│             │                           │    (dnf + pip)    │
│ roles/      │── uploaded to CVM ───────▶│ 2. CIS apply      │
│   cis_*     │      (bundled roles)      │    (cis_engine.py) │
│             │                           │ 3. Gate:          │
│             │                           │    fail_on_findings│
│             │◀── image-id ──────────────│ 4. CreateImage    │
└─────────────┘                           └──────────────────┘
```

Three phases executed by Packer on the ephemeral CVM:

1. **Install** — provisions ansible-core via dnf + pip inside the instance.
2. **Harden** — `ansible-local` runs the bundled cis-os engine (`cis_engine.py` + `rules.json`).
   Variables: `cis_mode: apply`, `cis_profile: L1/L2`, `cis_platform: server`.
3. **Gate** — in-role: `cis_fail_on_findings: true` + `cis_min_score: 0`.
   If any findings remain after remediation, `ansible-playbook` exits non-zero
   and Packer fails the build. No separate verify script needed.

### Design Decisions

**Bundled roles, no Galaxy.**
The cis-os engine is shipped in `roles/` alongside `ciscvm.py`. At build time the
tool copies the role into the workspace. No network dependency, no version drift.

**`ansible-local` over `ansible`.**
The Packer controller does not need SSH access into the cloud VPC — playbooks and
roles execute inside the instance.

**Build-time gate, no external audit.**
The gate is inside the Ansible role itself (`cis_fail_on_findings`). There is no
separate goss audit step. The hardened image is guaranteed to pass or not be created.

**Credentials and governance.**
AK/SK via environment variables only (`sensitive = true` in HCL). Ephemeral instances
are tagged and auto-recycled. Image tags record CIS level, OS, and benchmark.

## Profiles

| Profile | OS | SSH User | Role |
|---|---|---|---|
| `tencentos3` | TencentOS Server 3 | root | `roles/cis_tencentos3/` |
| `tencentos4` | TencentOS Server 4 | root | `roles/cis_tencentos4/` |

To switch, change `[build].profile` and `source_image_id` in `ciscvm.toml`.

Level 2 requires additional partitions (`/var`, `/var/tmp`, `/var/log`, `/var/log/audit`,
`/home` with `nodev`, `nosuid`, `noexec`). Configure partitions in the source image or via
`user_data` before building.

## CI Integration

```bash
export TENCENTCLOUD_SECRET_ID=xxx

```

Point downstream CVM / Auto Scaling / Terraform at the output `image_id`.
Pin the build machine to a dedicated VPC and security group.
